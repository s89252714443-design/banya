# Спа-комплекс на Алтае «Сила Духа»

Полностью автономная копия сайта [spasiladuha.ru](https://spasiladuha.ru/) (исходно собран на Tilda).
Все стили, скрипты, изображения и шрифты лежат локально — интернет для работы сайта не нужен.

## Структура

```
.
├── index.html              # Вся разметка страницы (один файл)
├── assets/
│   ├── css/                # 5 файлов: стили Tilda + подключение шрифтов
│   │   ├── google-fonts.css                    # @font-face -> assets/fonts/
│   │   ├── tilda-grid-3.0.min.css
│   │   ├── tilda-blocks-page43426613.min.css   # ← основные стили блоков страницы
│   │   ├── tilda-animation-2.0.min.css
│   │   └── tilda-popup-1.1.min.css
│   ├── js/                 # 15 файлов: jQuery + библиотеки Tilda
│   ├── media/              # 105 изображений: jpg, png, svg
│   └── fonts/              # 10 файлов woff2 (Manrope, Oranienbaum)
└── .claude/launch.json     # Конфиг локального dev-сервера
```

## Локальный запуск

Открывать `index.html` двойным кликом не стоит — часть скриптов Tilda не работает по протоколу `file://`.
Нужен любой статический сервер:

```bash
npx -y serve .
```

Затем открыть адрес, который выведет команда.

## Как вносить правки

- **Тексты и содержимое блоков** — прямо в `index.html`. Разметка не минифицирована,
  блоки размечены как `<div id="rec705087438" class="r t-rec" data-record-type="396">`,
  поиск по нужной фразе находит место сразу.
- **Стили** — `assets/css/tilda-blocks-page43426613.min.css`. Файл минифицирован;
  для точечных правок удобнее завести отдельный `assets/css/custom.css` и подключить
  его последним в `<head>`.
- **Картинки** — заменить файл в `assets/media/` с тем же именем, либо положить новый
  и поправить `src` / `data-original` в `index.html`.
- **Якорные ссылки меню** (`#about`, `#program`, `#rev`, `#contacts`, `#who`, `#ind`)
  переведены на относительные — навигация работает внутри копии.

### Важно: не трогайте высоты блоков

Блоки Tilda типа «zero» (`data-record-type="396"`) задают базовую высоту в CSS
(например, `602px`), а итоговую высоту и масштаб (`--zoom`) вычисляет скрипт
`tilda-zero-scale-1.0.min.js` при загрузке — под ширину окна пользователя.

Поэтому **нельзя** прописывать блокам жёсткие `height` в инлайн-стилях или правила
вида `#recNNN .t396__artboard { height: 955px !important; }`. Такие значения ломают
адаптивность: на широких экранах текст «разъезжается» и налезает на соседние блоки.
Именно этим страдает вариант, сохранённый через «Сохранить страницу как» в браузере
(см. ниже).

## Как собиралась копия

Копия собрана **из исходного HTML сайта**, а не из сохранённого браузером DOM.
Это принципиально: команда «Сохранить страницу как» пишет на диск состояние страницы
*после* выполнения JS, запекая в разметку вычисленные значения — `--zoom`, инлайновые
`height`, правила `height: …px !important`, классы `r_anim r_showed`, `opacity: 1`
и `transform-origin` на 258 элементах. Все они рассчитаны под то окно браузера,
в котором страницу сохраняли, и на других экранах дают сломанную вёрстку.

Корректность проверена сравнением с живым сайтом: измерены высоты всех 42 блоков
на трёх разрешениях (1600, 1280, 375 px) — **значения совпадают до пикселя**,
битых запросов и картинок нет.

После заливки: **Settings → Pages → Source: Deploy from a branch → `main` / `(root)`**.
Файл `.nojekyll` уже добавлен, чтобы Pages отдавал папку `assets` как есть.

## Что осталось внешним (и почему)

Это не недочёты копирования, а ссылки, которые ведут наружу по своей природе:

- **Счётчик статистики Tilda** — подгружается скриптом и продолжает обращаться к серверам
  Tilda. Если не нужен — удалите из `index.html` тег `<script>` с `id="tildastatscript"`.
- **`<link rel="canonical">` и `og:*`** в `<head>` указывают на боевой домен —
  поменяйте на новый адрес перед публикацией.
- Иконки сайта (`favicon`, `apple-touch-icon`) и внешние ссылки в подвале.

## Формы

Форм обратной связи в разметке нет — кнопки открывают попапы или ведут по якорям.
Ничего перенастраивать при переносе не требуется.
